ZIVAISHE PORTFOLIO — BACKEND / HOSTING SETUP

The website works immediately as a static site. The new Admin Dashboard becomes functional after Supabase is connected.

WHY SUPABASE INSTEAD OF FIREBASE FOR THIS BUILD
As of 2026, Firebase Cloud Storage requires the Blaze pay-as-you-go plan and a billing account. Supabase currently offers a free plan with Auth, database and 1 GB file storage, which is more suitable for this small owner-managed portfolio.

SUPABASE SETUP
1. Create an account at https://supabase.com and create a new Free project.
2. Authentication > Users: create your ONE owner user (email + strong password). Disable public sign-ups in Auth settings if available.
3. Storage > New bucket: create a PUBLIC bucket named: portfolio-files
4. SQL Editor: run the SQL below. Replace owner@example.com with the exact email used for your owner account.
5. Project Settings > API: copy Project URL and anon public key into js/backend-config.js.
6. Open admin.html through Live Server and sign in.

SQL TO CREATE TABLES AND SECURITY

create table if not exists public.site_settings (
  key text primary key,
  value text not null
);
create table if not exists public.research (
  id uuid primary key default gen_random_uuid(),
  title text not null, year integer, description text not null, tags text,
  file_url text not null, file_path text, created_at timestamptz default now()
);
create table if not exists public.projects (
  id uuid primary key default gen_random_uuid(),
  title text not null, category text, description text not null, tags text,
  file_url text not null, file_path text, created_at timestamptz default now()
);

alter table public.site_settings enable row level security;
alter table public.research enable row level security;
alter table public.projects enable row level security;

create policy "public read settings" on public.site_settings for select using (true);
create policy "public read research" on public.research for select using (true);
create policy "public read projects" on public.projects for select using (true);

create policy "owner settings write" on public.site_settings for all to authenticated using ((auth.jwt() ->> 'email') = 'owner@example.com') with check ((auth.jwt() ->> 'email') = 'owner@example.com');
create policy "owner research write" on public.research for all to authenticated using ((auth.jwt() ->> 'email') = 'owner@example.com') with check ((auth.jwt() ->> 'email') = 'owner@example.com');
create policy "owner projects write" on public.projects for all to authenticated using ((auth.jwt() ->> 'email') = 'owner@example.com') with check ((auth.jwt() ->> 'email') = 'owner@example.com');

STORAGE SECURITY
Because the public needs to download the CV/papers/projects, the bucket itself is public. Add an INSERT/UPDATE/DELETE storage policy restricted to the same owner email. In Supabase Storage > Policies for portfolio-files, create policies for authenticated users where:
(auth.jwt() ->> 'email') = 'owner@example.com'
for INSERT, UPDATE and DELETE. Public read comes from the public bucket setting.
